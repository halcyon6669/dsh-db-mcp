# 安全

谁能写，以及这些规则在调用方不是 DSH 时是否还成立。

一句话版本：所有决定「这条语句能不能碰数据库」的规则都在 Python 服务里，所以对面板、DSH 智能体和每一个外部 MCP 客户端一视同仁。而依赖 DSH 会话的那两项 —— 审计日志与单会话限制 —— 出了 DSH 就不存在。

## 三道安全闸门

三条独立的闸门决定一条语句能不能写入：

1. **全局开关** —— `<runtime>/settings.json` 里的 `allowWrite`，在 *数据源列表* 页的列表卡标题行里切换，就在分组输入框右边。默认关闭；关闭期间所有写入都会以 `user_error` 拒绝，并提示去打开开关。
2. **单源开关** —— 数据源上的 `readOnly`，默认开启。行上的开关可一键切换，开关旁边的字说明当前朝向。除了这个开关和它下面那个 DDL 开关，行上的东西（密码损坏提示、探测结果）都只是普通文字，所以能点的东西和看起来能点的东西是同一件。
3. **DDL** —— 数据源上的 `allowDdl`，默认关闭，是和可写开关并排的另一个开关。写数据和改结构是两件事：愿意接受 `insert` 的数据源，它的表结构可能并不归你管。关闭期间 `create`、`alter`、`drop`、`truncate`、`rename`、`grant`、`revoke` 在到达数据库之前就被拒绝，`insert`、`update`、`delete` 不受影响。这个开关只有在数据源可写时才有意义，所以只读行上根本不显示它——一个永远用不上的控件只是噪音。

可写的数据源可以写登录能看到的每一个模式 —— 不再有逐模式白名单。剩下的边界是数据库本身：能写 `hr.employees` 的登录，换个客户端照样能写。要硬限制，请同时给这个数据源一个更窄的 `GRANT`。

Python 服务在启动时读取全局开关，开关一动 Host 就重启它。在引擎允许的地方，只读还会在驱动层再拦一次（SQLite 用 `mode=ro`，PostgreSQL 用 `default_transaction_read_only`，MySQL 用 `SET SESSION TRANSACTION READ ONLY`）。

## 哪些规则在 DSH 之外仍然生效

三道闸门都在 Python 服务里，那才是真正打开连接、执行语句的进程。外部客户端的 SQL 根本不经过 DSH，所以只活在 Host 半边的规则对它无能为力。分界线就是这样：

| 规则 | 强制位置 | DSH 智能体 | 外部 MCP 客户端 |
| --- | --- | --- | --- |
| 全局写开关（`allowWrite`） | Python，子进程启动时从环境变量读 | 生效 | 生效 —— 开关翻转时 Host 会同时替换 HTTP 子进程 |
| 单源 `readOnly` | Python，每次调用都重读注册表 | 生效 | 生效 |
| `allowDdl` | Python，连目标模式都还没解析就判定 | 生效 | 生效 |
| 单会话限制（`mcp__db__session_scope`） | Host，按 DSH 会话 id 索引 | 生效 | 不生效 —— 外部客户端没有可索引的会话 |
| 审计日志 | Host，包在每次工具调用外面写 | 生效 | 不生效 —— 外部调用不会在 `logs/audit.jsonl` 留行 |
| 行数默认值（面板里的 `sample_rows`、`execute_sql`） | Host，调用前塞进参数 | 生效 | 不生效 —— 但服务端的硬上限照旧 |
| *工具* 标签里被关掉的工具 | Host，注册工具时过滤 | 生效 | 不生效 —— Python 服务照旧发布全部工具 |

两个值得知道的后果：

- 在 *工具* 标签关掉一个工具，只是把模型能看见的清单削短了，能力并没有收回：外部客户端照样能调它，面板自己的 `/mcp/call` 接口也是。
- 因为 `allowWrite` 只读一次，翻动它会同时替换两个 Python 子进程 —— 智能体背后的 stdio 那个，和外部客户端背后的 HTTP 那个。两者回到同一个端口，所以已经指向该端点的客户端不需要重新配置。

## DDL

读取不受限制：智能体能看登录有权限看到的每一个模式，可写的数据源也能写其中每一个。数据源上剩下的唯一选择是它能不能改数据库结构。

行上的 DDL 开关一键打开。含义就是字面意思 —— 没开启的数据源上 `create`、`alter`、`drop`、`truncate`、`rename`、`grant`、`revoke` 在到达数据库之前就被拒绝；`insert`、`update`、`delete` 无论开关如何都照常。**编辑** → **更多设置** 里也有同一个开关，叫 *允许 DDL*，所以行上和表单始终一致。

拦截发生在 Python 服务里，因此对智能体、HTTP 接口和面板都同样生效：

- 一批语句里每一条都会检查；前面加 `--` 注释或用 `;` 拼接都藏不住。
- 读取（`select`、`with`、`show`、`explain` 等）永远放行。
- `insert`、`update`、`delete` 在可写数据源上放行。
- 改变数据库结构的语句在数据源没有开启 DDL 时一律拒绝；`truncate` 也算，因为它清空整张表，破坏力和 `drop` 一样彻底。

这是守卫，不是授权。它拦住智能体改动没被允许改的模式，真正的边界仍在数据库。要硬限制，请同时给这个数据源一个更窄的 `GRANT`。

已存口令是加密落盘的。`secrets.json` 里每个数据源存的是 AES-256-GCM 信封，密钥就在旁边的 `secret.key`（0600，首次使用时生成）。单独一份 `secrets.json` —— 备份、同步目录、贴进工单的文件 —— 不再带任何口令；把信封挪到别的数据源上也解不开，不会悄悄返回错的口令。以你的账号运行的程序仍能同时读到两个文件，所以面板在口令解不开时会在行上标 *已存口令无法解密*，让你重新输入。删掉 `secret.key` 可一次性让所有已存口令失效，这是最快的整体撤销方式。

## 限制单个会话能访问的数据源

可以把这个会话限制在部分数据源上。直接用自然语言说 —— *「本会话只用 pg-demo 和 oracle-demo」* —— 智能体会用这些标识符调用 `mcp__db__session_scope` 工具。不用填表，也不用改文件；标识符就是列表里每个名称下方显示的那一串。

该会话存在限制时：

- `list_datasources` 只返回允许的那几条；
- 调用里写了别的数据源，会以 `user_error` 拒绝；
- 调用里不写 `datasource`，会在只有一个允许项时自动用它，否则提示可用的标识符；
- `test_connection` 不能用内联的连接串，否则会绕过名单。

说 *「取消本会话的限制」*（或让工具用 `all: true`）即可解除。没有保存限制的会话仍然能访问全部数据源；*数据源列表* 标签里的「会话访问范围」卡会列出被限制的会话，每个会话带一个移除按钮，还有一个 **全部清除**，会话被销毁时限制会被真正删除，会话被归档时则**只是停放到同一文件里**，取消归档后会原样还回来：你主动设的限制不该因为归档一次就没了。手动移除会连停放的那份一起删掉，否则下次取消归档会把你故意删掉的东西复活。这张卡始终在，没有会话受限时写着「没有会话被限制」。它是一张三列表格——会话 id、会话名、访问的数据库——**默认就是展开的**：id、标题、数据源是三样不同的东西，按列对齐远比一行流水文字好读；而且这限制是智能体设的，面板是唯一能查看它的地方，藏在一次点击后面等于让人去找。表头固定、表格自己滚动，列表再长也不会把页面顶来顶去。每行的会话 id 完整显示，因为文件就是按 id 索引的，缩写会让两个会话看起来一样；宿主知道标题时会把标题显示在「会话名」列，不知道就写「未命名」。这个限制是会话级的便利开关，不是安全边界：运行时目录里的文件对你自己的账号始终可读。

## TLS

数据源上的 `sslMode` 决定驱动实际协商什么，取值映射见 [reference.md](reference.md#sslmode)。有两点需要先知道：

- **openGauss 不校验证书。** 驱动的 TLS 入口被 shim 接管（Python 3.12 移除了 `ssl.wrap_socket`），shim 以 `CERT_NONE` 运行，所以连到 openGauss 的链路是加密的，但没有认证：中间人可以出示任意证书。这类服务器请放在你能控制的网络里，或者在前面做 TLS 终止。
- **需要 SSH 隧道的 DBeaver 连接不会被导入。** DBeaver 把隧道放在 `configuration.handlers` 里，而连接字段里写的是隧道的本地端，直接导入会得到一个指向 `localhost` 的数据源。导入列表会把这类连接连同原因一起显示出来，且没有勾选框；走代理的 handler 同样处理。确实需要的话，请换一种方式把数据库端点暴露出来再手动添加。

## 审计日志

每次 MCP 工具调用都会往 `<runtime>/logs/audit.jsonl`（0600）追加一行 JSON：时间、工具、数据源、耗时、行数、截断到 2000 字符的 SQL，以及失败时的错误。结果行本身从不记录。文件到 512 KiB 会轮转为 `audit.1.jsonl`，日志可用 `auditLog: false` 关闭。

面板按 **你本机的时钟** 显示最近十几次记录，**带日期**，昨天和一小时前的调用不会混在一起；文件里保存的是 UTC，以便跨机器比较。悬停时显示同一时刻与时区。

语句才是你打开这一页真正要看的东西，所以它单独占一块下沉的底色：等宽字体、正文墨色而不是灰色提示色，左侧一条竖线 —— 成功是蓝色，失败是红色。长语句在这块里折行，超过十来行就在块内滚动，不会把后面的记录顶出屏幕。
